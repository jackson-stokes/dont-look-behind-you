LD2451 decoder on the Pi, both radars (82bdef6), Pi 5 "hoopty", 2026-11-12 (Gage)
==================================================================================
Purpose: check that cap-radar decodes real target frames from both radars and
that decoded targets reach the store.

Setup: dlby-super with store, fuse-hub, cap-radar (right, /dev/ttyAMA2) and
cap-radar-left (/dev/ttyAMA4); no sonar, so fuse-hub never logs `healthy` (it
needs every sensor up). One person walked out ~10-15 m from each radar in turn
and walked back toward it.

Commands:
  cd ~/dlby-src && git checkout gagebranch && git pull && make && make test 2>&1 | tail -3
  export DLBY_RUN_DIR=$HOME/dlby-demo/run DLBY_LOG_DIR=$HOME/dlby-demo/log DLBY_BIN_DIR=$HOME/dlby-demo/bin
  export DLBY_CHILDREN=store,fuse-hub,cap-radar,cap-radar-left
  build/dlby-super 2>&1 | tee ~/dlby-demo/super.log           (T1)
  grep -E 'target n=|bad_payload' ~/dlby-demo/super.log | head -20; build/tools/dlby-logcat ~/dlby-demo/log   (T2)

The run was ended with Ctrl-C in T1, which also stopped tee, so the exit lines
are not in the log.

Reading:
  - Both radars decode: target lines from cap-radar and cap-radar-left, and no
    bad_payload line, so every target frame matched the layout.
  - speed_cms=-83 is 3 km/h approaching (walking pace); range_cm falls 400 -> 200
    (right) and 300 -> 200 (left); angles -14..0 deg, near straight ahead.
  - target lines are rate limited: count= is how many target frames each line
    covered, so the first line logged is not the furthest detection.
  - Store: radar_targets=72 records carry targets; bad=0, contiguous=1.
  - store_back dropped=1 / gap_msg=1: one message the hub sent before store was
    ready at startup, recorded as a gap (as designed).
