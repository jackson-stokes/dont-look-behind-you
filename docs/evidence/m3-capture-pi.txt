Findings
- Both real sensors reach store through the real pipeline: run 1 stored 1249
  records with bad=0 contiguous=1; every message cap-* sent was forwarded.
- Sonar: 0 missed pings and 0 timer overruns over 1904 pings on absolute 60 ms
  deadlines. The one unsent ping per run was in flight at SIGTERM.
- Open air gave far=11 (echo > 25 ms, sent as SONAR_NO_ECHO) and no stuck_high:
  this HC-SR04 ends its no-target pulse inside the 60 ms ping.
- Radar: one empty frame every ~1.44 s (50 in ~72 s), 0 bad frames, still no
  target frame captured (target_frames=0).
- DESIGN.md §3 radar row on hardware: TX pulled -> cap-radar radar_silent and
  fuse-hub "degraded lost=radar reason=stale"; reconnected -> sensor_up, healthy.
- store_back dropped=1 in run 2: store and hub were launched on one line, so the
  hub's first state record went out before store was listening; the hub counted
  it and logged the gap as designed. Under dlby-super, store starts first.
- Range values are not checked here: nothing logs per ping (DESIGN.md §3) and
  dlby-logcat only counts records.
