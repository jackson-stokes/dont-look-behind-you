==================================================================================
Purpose: verify the LD2451 target layout before writing the decoder
(cap-radar.c sends ntargets=0 until this; msg.h radar_target PROVISIONAL).

Setup: radar pointed down a clear stretch, waist height, one person.
  idle  40 s, nobody in view
  walk  40 s, start at the radar, walk straight out ~15 m, turn, walk back
  fast  40 s, same out-and-back, jogging

Commands (dlby-super stopped; nothing else reading the UART):
  stty -F /dev/ttyAMA2 115200 raw -echo
  for p in idle walk fast; do read -p "Enter to start '$p' (40 s) " _; timeout 40 cat /dev/ttyAMA2 > $p.bin; echo "$p: $(stat -c %s $p.bin) bytes"; done
  hex() { od -An -tx1 -v "$1" | tr -d ' \n'; }
  for f in idle walk fast; do echo "== $f"; hex $f.bin | grep -o 'f4f3f2f1....' | sort | uniq -c; done
  for f in walk fast; do echo "== $f"; hex $f.bin | sed 's/f4f3f2f1/\nf4f3f2f1/g' | grep -v '^f4f3f2f10000' | grep .; done

Observations:
  - Only approaching targets are reported: each run starts AT the radar, but the
    first target frame is already at 8-9 m and distance only decreases. The
    outbound legs produced empty frames only.
  - Target frames arrive much faster than the ~1.4 s empty-frame rate.
  - Nearest reported distance 2 m; furthest 9 m for a person on foot.
  - Resolution is 1 m and 1 km/h.

Not verified by this capture: direction 00, the multi-target stride (2 targets
